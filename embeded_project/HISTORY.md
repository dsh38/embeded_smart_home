# 📜 스마트홈 IoT 시스템 프로젝트 변천사 (HISTORY.md)

이 문서는 스마트홈 IoT 시스템 프로젝트의 시작 초안부터 배포 직전 단계까지의 사용자 요구사항에 따른 모든 아키텍처 변경 이력 및 개선 흐름을 시간 순으로 상세히 기록한 문서입니다.

## 📅 버전별 변경 및 개선 이력

### 📌 [v1.0.0] 프로젝트 시작 및 핵심 초안 설계
* **초안 요구사항**:
  * 라즈베리파이 4B 타겟의 Python 기반 스마트홈 웹 애플리케이션.
  * 별도의 스마트홈 Hub(Zigbee 등) 없이 라즈베리파이의 GPIO를 통한 DHT22 온습도 측정 및 IR(적외선) 송출 기반 에어컨 제어.
  * 개발 유지보수를 원활히 하기 위한 MVC 패턴 적용.
  * 회원가입 기능 배제, 초기 계정 `admin`/`admin` 기반의 로그인(자동 로그인 지원 및 비밀번호 암호화 저장).
  * 메인 대시보드 온습도 10초 주기 실시간 갱신 표기.
  * 등록 가전이 없으면 '기기 등록' 버튼 표기 (등록은 삼성/LG 에어컨으로 제한, 향후 제습기 확장 고려).
  * 등록 기기 클릭 시 상세 패널로 이동하여 모드(리스트박스), 온도(18~30도 입력/선택 대조), 바람세기(강/중/약) 설정 및 확인/취소 조작 제공.
* **설계 적용**:
  * `app.py` 및 Flask 기둥 수립.
  * sqlite3 DB 스키마 및 DB 모델 인터페이스(User, Device) 초안 구상.

### 📌 [v2.0.0] 데이터 저장소 간소화 및 테마 토글 탑재
* **요구사항 변경**:
  * 회원가입 기능이 없으므로 데이터베이스 서버나 SQL 파일 없이 **파일 기반 저장(JSON 등)**으로 간소화 처리 요청.
  * 윈도우용 Mock 테스트는 고려하지 않고, 원격 SSH 라즈베리파이 타겟 환경에 직접 이식될 `pigpio` 전용 삼성/LG 송신 코드( recorded_signals.json ) 결합 요청.
  * 기본 테마는 **Dark 모드**로 하되, 메인 패널 하단 Footer에서 **Dark / White 테마 전환 스위치** 추가 요청.
* **설계 적용**:
  * SQL DB 설계를 전면 취소하고 `data/config.json` 단일 파일 입출력 모델(`AuthModel`, `DeviceModel`)로 재설계.
  * 패스워드 저장 방식을 `werkzeug.security` (`generate_password_hash` / `check_password_hash`)의 PBKDF2 암호 해싱 저장으로 구현.
  * 기존 적외선 리모콘 송신 테스트용 `recorded_signals.json`을 읽어 삼성 신호를 쏘고, LG 에어컨의 28비트 데이터 생성 펄스 생성 로직을 `UniversalACTransmitter` 클래스로 이식하여 드라이버 추상화.
  * 다크 모드 기본 테마 적용 및 Footer 테마 토글 결합.

### 📌 [v4.0.0] Cloudflare 연결 IP 복원 및 브루트포스 로그인 방지 구현
* **요구사항 변경**:
  * Cloudflare Tunnel을 사용할 때 프록시 IP(`127.0.0.1`)만 기록되어 방문자 필터링이 불가능한 현상 개선 요청.
  * 악의적 계정 대조 공격을 막기 위해 한 IP에서 **10회 로그인 실패 시 24시간 동안 로그인 시도를 강제 차단**하는 차단 시스템 및 차단/차단 상태 재시도 시 서버 콘솔에 `[WARNING]` 경고 로그 표출 요청.
* **설계 적용**:
  * `get_client_ip(request)` 헬퍼 함수를 구현하여 `CF-Connecting-IP` 헤더가 존재하면 방문자 공인 IP를 최우선 캡처하고, 없으면 일반 프록시 헤더 `X-Forwarded-For`에서, 둘 다 없는 경우 로컬 소켓 IP를 읽어오는 전원 호환 IP 획득 로직 탑재.
  * Flask 진입부에 `ProxyFix` WSGI 미들웨어를 통합하여 Flask 실행 터미널 표준 액세스 로그 자체에서도 `127.0.0.1` 대신 사용자의 실제 외부 공인 IP가 정상 기록되도록 버그 수정.
  * IP별 실패 카운트와 차단 만료일시를 영구 관리하는 `data/login_attempts.json` 파일 데이터 모델(`LoginAttemptTracker`) 신설.
  * 로그인 시도 차단 실행 시점 및 차단 상태 시도 시점에 `logging.warning()` 경고를 발생시켜 서버 표준 콘솔에 명확한 로그가 표출되도록 설계 결합.

### 📌 [v8.0.0] 1602 LCD 접속 주소 좌우 스크롤(Marquee) 및 데몬 안정화
* **요구사항 변경**:
  * 접속 IP 주소와 포트 번호(예: `192.168.12.34:5000` - 18자)가 결합되었을 때 1602 LCD의 한 줄 제한(16자)을 넘겨 잘리는 문제 해결 요청.
* **설계 적용**:
  * 접속 주소가 16자를 초과하는 경우, 전광판처럼 첫 글자부터 마지막 글자까지 한 칸씩 좌측으로 이동해 전체를 확인할 수 있도록 하는 **텍스트 좌우 스크롤(Marquee Scroll)** 기능 탑재.
  * 가독성을 고려해 첫 화면은 1.0초간 멈추고, 스크롤 시에는 0.35초 간격으로 문자열을 흐르게 하고, 끝에 도달하면 1.5초간 머무는 정밀 딜레이 시스템 구현. 스크롤이 완전히 종료되면 추가 대기 시간 없이 즉시 온습도 화면으로 자연스럽게 복귀.
  * Flask의 리로더 기동 이전에 `app.debug = True` 설정을 확실히 전행하여, Flask 디버그 모드가 2회 구동되는 과정에서 백그라운드 LCD 데몬 스레드가 2개 생성되어 I2C 버스 자원 충돌 및 중복 출력이 발생하던 버그 수정.
  * I2C LCD 가상 시뮬레이터 드라이버가 Line 2만 변경되었을 때에도 변경 결과를 콘솔에 가상 렌더링하도록 개선하여, 스크롤 동작이 터미널 화면에 정상적으로 애니메이션되는지 시각화 검증 가능하도록 패치.

### 📌 [v8.1.0] 삼성 에어컨 IR 송출 pigpiod 크래시 방지 및 재연결 보완 (Hotfix)
* **요구사항 변경**:
  * 삼성 에어컨의 `power_off` 등 매우 긴 IR 코드를 송출할 때 `pigpiod` 데몬과의 연결이 끊어지면서 `Connection reset by peer` 에러가 발생하고, 이후 모든 제어가 `Broken pipe` 상태로 먹통이 되는 버그 핫픽스 요청.
* **설계 적용**:
  * **크래시 원인 식별**: `pigpio`는 단일 웨이브폼(`wave_create`)당 최대 5,460개 이하의 펄스만 생성할 수 있습니다. 삼성 에어컨 `power_off` 신호는 349개의 마크/스페이스 타이밍을 가지고 있으며, 38kHz 변조 펄스를 raw 리스트 형태로 직접 생성 시 총 7,136개의 펄스가 유발되어 `pigpiod` 데몬이 메모리 한계를 넘고 강제 충돌 종료(Crash)를 일으킨 것이 확인되었습니다.
  * **wave_chain 기반의 중복 파형 압축 송출 기법 도입**:
    * 송출할 신호의 타이밍 오차 지터를 걸러내기 위해 마크/스페이스 길이를 50us 단위로 반올림하여 버킷화합니다.
    * 50us 단위로 표준화된 고유 마크 및 스페이스 신호는 단 몇 개(약 5~10개 미만)의 개별 웨이브폼 ID로 `pigpiod`에 미리 등록하여 펄스 개수를 극적으로 최소화합니다.
    * 생성된 고유 웨이브폼 ID들을 순서대로 `pi.wave_chain()` 리스트에 태워 순차 조합 송출함으로써, 단일 펄스 수 제한(5,460개)을 완벽히 우회하고 `pigpiod`가 크래시되지 않도록 복원하였습니다.
    * 송출 완료 후 `pi.wave_delete()`를 호출하여 사용된 웨이브폼 메모리 공간을 즉각 해제하도록 가비지 컬렉션을 연동하였습니다.
  * **pigpiod 데몬 소켓 자동 재연결(Auto-Reconnect) 구조 추가**:
    * 혹시 모를 데몬 재시작 또는 소켓 단선 시 `Broken pipe` 상태로 서비스가 정지되는 것을 막기 위해, IR 송출 직전에 소켓 연결성을 검사하여 연결 유실 시 Flask 서버 재기동 없이 데몬 소켓 재연결 및 GPIO 모드 설정을 자동으로 시도하고 복구하는 안정 장치를 이식하였습니다.
